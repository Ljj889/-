# 多 Agent 编排模式库

2026 年生产级多 Agent 系统收敛出的六种编排模式。派活前先按决策矩阵选型，不默认只用一种。

## 六种模式

### 1. Sequential Pipeline（串行流水线）
Agent A → Agent B → Agent C，线性链式，每步处理上一步输出。
- **适用**：任务有清晰有序阶段、每步依赖前一步（如：调研 → 分析 → 出报告）
- **注意**：每步先校验输入；中间结果持久化便于调试恢复

### 2. Parallel Fan-out / Fan-in（并行扇出/扇入）
协调者把独立子任务分发给多个并行 Agent，再汇总。
- **适用**：独立子任务可同时处理（如：三个模块并行开发）
- **注意**：给每个并行 Agent 设时间上限，防止单个拖垮整体；单个失败时仍用其余结果产出部分成果

### 3. Router / Dispatcher（路由器）
路由 Agent 按请求类型分类，分发给不同专业 Agent。
- **适用**：请求类型多样、各需不同专长
- **注意**：路由用轻量模型即可；加 fallback 类别兜底

### 4. Supervisor / Worker（监督者-工人）★ 默认
监督者拆任务 → 派发给工人 → 审查产出 → 要求修订 → 汇总。
- **适用**：质量要求高、需要迭代（家俊六层框架的主形态）
- **注意**：审查意见必须具体可执行；修订循环设上限

### 5. Hierarchical（分层编排）
顶层编排者拆解 → 委派给专家 Agent → 部分专家内部再用子流水线。
- **适用**：复杂任务混合多种形态
- **注意**：先掌握简单模式再进化到分层，不要一上来就上复杂编排

### 6. Swarm（群体）
多个对等 Agent 并行探索不同来源，共识 Agent 汇总。
- **适用**：信息搜集、竞品分析、多角度调研
- **注意**：只用于探索型任务，不适合需要强一致性控制的开发任务

## 决策矩阵

| 你的情况 | 选哪种 |
|---|---|
| 独立子任务可并行 | Parallel Fan-out/Fan-in |
| 阶段严格顺序依赖 | Sequential Pipeline |
| 请求类型多样需分类 | Router/Dispatcher |
| 质量关键、需审查迭代 | Supervisor/Worker |
| 任务复杂混合 | Hierarchical |
| 多源信息调研 | Swarm |

## 生产注意事项（全部模式通用）

1. **Agent 数量**：3-7 个最佳；>10 个是过度拆分（考虑合并或把部分 Agent 降级为工具）。
2. **接口合约先行**：每个 Agent 的输入/输出用 JSON schema 定义（见 task_templates.md），不用自由文本。
3. **成本预期**：多 Agent 系统 token 消耗约为单 Agent 的 10-15 倍——上下文重复 + 协调开销 + 审查循环。派活前先估预算。
4. **模型路由**：路由/分类用轻量档（lite），复杂推理用重型档（reasoning），混合模型可省 50-70% 成本。
5. **先建编排再建 Agent**：流程没验证前不要写真实 Agent，先用假结果跑通链路。
6. **可观测**：记录每次派发（时间、Agent、档位、结果），出错才能定位是哪一环。
7. **数据最小化**：只把 Agent 需要的字段传给它，不需要的数据不外泄（PII 在边界掩码）。
