# real-source-repro · 真实源码函数复现

## 适用判定

**当** 需要回答"这段逻辑到底有没有问题 / 它实际发出去了什么"时：
- 现象类 bug 的根因判定（rule 80 取证优先 → rule 41 归因闭环）；
- 接手他人（或上会话）给出的**推断性根因**（rule 82 ②：`[已推断]` 必须先复现才允许落码）；
- 效果类问题的载荷级取证（发给服务端/下游的内容长什么样）。

**易犯** 两种偷懒：
1. **读码推断就下结论**：推理链看着成立，但真实数据带刺（引号、全角标点、分片边界、编码）；
2. **复刻一份逻辑自测**：自己重写一遍被测逻辑来"证明"原逻辑有问题——**复刻通过 ≠ 原逻辑正确**（rule 73④ 明令禁止复刻逻辑当验证）。

**护栏**：把**真实源文件的相关片段**交给真实工具链转译，取出私有函数，喂**真实数据**，打印"实际输出"。今天实测：一次跑出嵌套 `<cot>` + 孤儿闭合标签 + 永不命中的等值匹配分支（三缺陷同屏）。

## 三步手法

```bash
# 1) 定位源码片段：从某个模块级常量/函数到下一个稳定边界（函数原型/导出行）
#    取"最小可自洽切片"，避免拉进 import 依赖（私有函数通常只依赖字面量与彼此）

# 2) 用真实工具链转译后再求值（TS 类型注解必须先剥掉）
node -e "
const esbuild=require('esbuild'), fs=require('fs');
const src=fs.readFileSync('src/<module>.ts','utf8');
const a=src.indexOf('<起始锚点，如 const COT_SEGMENT_MAX>');
const b=src.indexOf('<结束锚点，如 function clamp(>');
const js=esbuild.transformSync(src.slice(a,b),{loader:'ts'}).code;   // 真实源码文本 + 真实转译器
const M=new Function(js+'\nreturn {<f1>,<f2>}')();
"
# 3) 喂真实数据 → 打印"实际输出"（不是"是否符合预期"）：
#    数据来源优先级：用户日志原文 / 运行时 DB 值 / 存量文件内容 / 夹具（最后才造）
```

要点：
- **切片边界要稳**：用模块级常量名、`function xxx(`、`export ...` 等稳定锚点，别用行号（会漂移）。
- **避免 import 依赖**：只切自洽片段；若函数依赖外部导入（如字典常量），改为断言它调用前后的字符串形态，或用 `--external` bundle（见 ts-smoke-harness）。
- **临时脚本 `zz-*` 命名、跑完必删**（G-005）。
- **打印"实际发送/实际写出"的内容**：`JSON.stringify(输出)` 比"断言等于期望"更能说服人（也能暴露期望本身写错）。

## 断言写什么

- **畸形载荷可见**：嵌套标签、重复包裹、转义缺失、全角/半角混用、空值兜底
- **分支可达性**：今天顺带发现"等值匹配键永不命中"（→ 属 R-007 僵尸家族：有代码、有意图、永不生效）
- **边界数据**：分片切断处（`<c` + `ot ...>`）、引号包裹、漏闭合

## 实测战果（2026-09-12）

| 修复 | 复现产出 | 价值 |
|---|---|---|
| Fix1（分片防击穿） | 提取 `mayBeOpenTagTail/mayBeCloseTagTail` + 17 用例（含 `<c` 挂起、`<cotx` 不误伤、超长放行） | 判据上线前就验住 |
| Fix5（bidi 逐句管道） | 修复前：`发送 = <cot text="X"><cot text="gentle·mid，语气轻软">…`（嵌套=1）；修复后：nested=0、LLM 风格命中 1/2 | 一次定位真凶 + 修活僵尸分支 |

## 纪律

- 复现脚本与输出**进交付说明**（证据链），临时文件不进仓库（rule 42 + G-005）
- 复现结论要标 `[已复现]`（rule 82 ②）——这是"根因"被采信的门槛
- 复现失败（切片切不出来）不是"没问题"，而是"未验证" → 进未验证项清单，别静默降级
