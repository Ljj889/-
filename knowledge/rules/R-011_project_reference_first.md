# R-011 项目内参照物优先

**当** 要改/新增任何交互、渲染、IPC、状态管理行为时（不只排错——**开发前同样适用**）→ **易犯** 直接从零设计实现（"这个需求我写一个……"），而项目里几乎总有**已跑通、已验证**的同类实现（拖拽怎么做的、浮窗位置怎么管、IPC 怎么包装、错误怎么上报）——从零写 = 重造轮子 + 行为与既有实现不一致 + 丢掉旧实现踩过的坑 → **护栏**：

1. **动手前先 grep 项目内参照（rule 64 检索序第一环，最廉先验——秒级）**：按"行为关键词 + 技术词"搜（如拖拽→`drag|mousedown|setBounds`；浮窗→`setPosition|bounds`；持久化→`store|save|db.write`）。找到参照 → **先读再改**，新实现必须说明"与参照的差异及为什么"（说不清差异 = 应该直接复用参照）。
2. **找不到参照才升级检索**：`read_knowledge(问题域)`（rule 59）→ WebSearch → 最小复现（rule 41）。**排序原则 = 取证成本从廉到贵**：grep 秒级 < 经验库 < 搜索 < 复现。
3. **参照实现本身要验证过**：grep 到的代码须确认"已验证"（有测试/在用/无 TODO 债）——抄一个僵尸实现（R-007）等于没抄。

**关联**：rule 64（纠错先检索——本资产是其第一环"项目内参照"的场景扩展）、rule 68 ④（重复代码查重——审查侧镜像）、rule 46（复用优先的编排出口）、R-007（僵尸能力——参照有效性校验）。
