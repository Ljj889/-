# R-012 幂等导入必须留痕

**当** 实现"首启导入 / 默认值注入 / 分发包预置"这类**一次写入 + 幂等标记**的功能时（`*_imported='1'`、`seeded=true`、migration 门控）→ **易犯** 三件事同时发生：
1. 迭代后新加的配置项**不会重导**（标记已写死）——功能"改了但没生效"，且**没有任何日志**提示"已跳过"（日志只在首次导入时打）；
2. 判据是"未动过才写"（保护用户已改值）时，**被保护而跳过的字段也不打日志** → 开发者无法区分"没导入"与"导入了但被保护"；
3. 交付/验收清单不写"哪些变更只对新档生效" → 用户在自己机器上测（老档）→ 判定"你没改"或"改坏了"。

实测（番茄宠物V2，2026-09-12）：`preset_imported='1'` + `personalize_imported='1'` 双命中——补音色键、补人设全文，在作者机上**均不生效**，只有净机（或清标记）才生效；两次都是靠"读 SQLite 值 + 比对预设文件"才发现。

**护栏**：

1. **跳过必打日志**：`[preset] skipped: already imported (mark=1)`；文件缺失、解析失败、被保护跳过，三类分支各一条日志（rule 42：无日志 = 未验证）。
2. **字段级可观测**：`imported N/M` 之外，逐条打 `skip(key, reason=user-set|default-equal|empty)`，让"少导了几个"一眼可查。
3. **版本化重导**：分发包迭代场景引入 `*_imported_version`（或内容哈希）——版本变化时允许**对未改动字段**重导，只保护真正被用户改过的键。
4. **验收清单显式标注**：交付说明必须写"本次新增配置仅在**新档/净机**生效"；若要求老档也生效 → 给出清标记/删档案/手填的操作卡（rule 80 用户操作卡）。
5. **核对方法写进交付**：`sqlite3`/better-sqlite3 直读设置表 + 与预设文件逐键比对（实测手法），别靠"我改了文件"自证。

**关联**：rule 42（验证证据纪律）、rule 72 / R-007（僵尸家族——本资产是其"配置侧"变体：能力在、链路在，但**状态把新值吞了**）、rule 80（验收三要素 + 用户操作卡）、R-010（构建配置静默失效——同属"三层全绿但功能没生效"家族）、rule 76（分发链路唯一真相源）。
