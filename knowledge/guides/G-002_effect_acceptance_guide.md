# G-002 效果类验收指南（rule 61 的操作手册）

**当** 验收"情绪像不像 / 好不好听 / 顺不顺眼 / 自不自然"这类**主观体验**时 → **易犯** 用 dry-run/单测绿冒充效果对（AI 伴侣实战：111 测试全绿但情绪"听不出"，到 W4 才人耳暴露）→ **护栏**（业界方法论，rule 61 的展开）：

## 1. 评分方法（三个协议按场景选）
| 协议 | 打分 | 适用 | 要点 |
|---|---|---|---|
| **MOS**（ITU-T P.800） | 绝对 1-5 | 单版本整体质量 | "人耳是最终的尺度" |
| **CMOS / SBS** | 相对 -3~+3 | 迭代对比（V1 vs V2） | "B 比 A 好多少？"对微小改进更敏感 |
| **MUSHRA** | 带锚点多样本盲测 | 高保真精细对比 | Reference + Anchor + 多个候选 |

## 2. 维度拆解（不要只问"好不好听"）
| 维度 | 问什么 |
|---|---|
| 自然度 Naturalness | 像真人吗？有机械感吗？ |
| 韵律感 Prosody | 停顿/重音符合语义逻辑吗？ |
| 清晰度 Articulation | 有没有吞音/含糊？ |
| **情感符合度 Emotion Match** | 给定"愤怒"，听起来愤怒吗？（效果类最常用） |
| 音质 Sound Quality | 电流声/爆破音？ |

## 3. 执行要点（个人项目简化版）
- **盲测**：隐藏版本信息，防先入为主（自己测也别知道哪个是哪个）
- **随机顺序**：样本打乱；同一句话的不同版本不连续听（记忆干扰）
- **样本设计**：3-10 秒/样本，覆盖多情感 × 多文本类型；对照真实人类样本
- **评分指南**：先听 1 分和 5 分样例建立标尺
- **统计**：剔除全 5/全 1 极端值；多人评分取均值 + 置信区间（个人项目 ≥1 人可接受，注明）
- **MOS 基准**：4.5+ 接近真人（商业级）/ 4.0-4.5 高质量 / 3.5-4.0 可接受

## 4. 用评分指导优化（MOS 不只是打分）
- "愤怒"得分低 → 可能语速过快听不清
- 克隆音色 MOS 不稳定 → 参考音频质量波动
- 不同人群分差大 → 地域语言习惯问题

## 5. 与框架衔接
- rule 61：效果类任务 Wave 前置"人耳/MOS 验收点" + 试错预算上限 + 审查主观预检
- 分层验证：音色×资源×提示词×强度 4 维交叉，一次只动一维定位根因（多宠语音 P9 案例）
- 效果类审查：审查 Agent 抓不了效果质量 → 留"主观预检"记录（rule 61/D4）

## 6. 净机模拟：验证"新用户/好友首启"路径（v2 · 2026-09-12 番茄宠物V2）

- **当** 要验证"新用户首启体验"（预置注入、首次引导、默认档案、默认主题）→ **易犯** 拿自己机器"跑通了"当证据：**自己的档案早已导入过**（幂等标记已写），新档路径根本没走到（实测：用户"自己电脑解压跑了没问题"用的就是已有档案；改用干净档案 + 打包 exe 才验到 `imported 10/10`、`imported 4/5`、导览自动弹）。
- **护栏**：用 **`--user-data-dir=<临时目录>`** 启动（Electron 生效）→ 干净档案，**不动真实数据、可与真实实例并存**验证；打包版同样适用（`<App>.exe --user-data-dir=...`）。
- **别走的路**：改/删用户档案名（Windows 上常被句柄占用拒绝——实测 `Rename-Item` Access Denied；且风险高、不可并发）。
- 验收声明仍须带**三要素**（rule 80）：档案状态（新档|旧档）× 代码来源（源码|产物|asar）× 启动方式（dev|packaged）。
- 净机跑完**清理**：关实例 + 删临时档案目录（记进交付说明）。

## 7. 审美/口吻类低信息量反馈的"一句话确认"（v2）

- **当** 用户给"看着不对 / 正规一点 / 太丑 / 不太行"这类反馈 → 先给**一句话确认**："我理解 = X；备选 = Y/Z；**默认按 X 做**，你否了我改"（rule 61 v3.16.0 扩展）。
- **理由**：不阻塞（用户可能正忙）、可回退（一行命令/一次改动）、不反复追问；把"我理解 = X"写进交付说明，用户一看就知道要不要否。
- 实测：用户一句"数字格式正规一点" → 我理解为"行楷数字不正规"（正解），但也可能是"任务名那行" → 一句话确认能把这个猜测成本降到最低。
